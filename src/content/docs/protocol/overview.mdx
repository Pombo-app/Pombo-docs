Pombo is a communication protocol built on Streamr and Polygon, implemented in the Pombo web and Android apps. Each client is a Streamr node, so messages travel peer to peer with no server in between. Ownership and permissions live on Polygon; storage providers keep history; a relay wakes sleeping devices.

<LinkCard title="Interactive protocol map" description="Every component and link, with step-by-step stories for each channel type." href="https://pombo.cc/map/" />

## Components

| Component | Role | Reached over |
| --- | --- | --- |
| Clients | Hold the account key; run a Streamr node; encrypt, sign and verify | |
| Streamr network | Carries every [stream](/protocol/streams/) peer to peer | pub/sub |
| Polygon | Stream registry and permissions, storage assignments, storage-node registry, [gate contracts](/protocol/access/) | JSON-RPC |
| The Graph | Indexes the Streamr registry: listed channels, storage assignments, stream metadata | GraphQL over HTTPS |
| [Storage providers](/protocol/storage/) | Keep stored streams and serve history | HTTPS |
| [Push relay](/protocol/push/) | Wakes devices by tag | the push stream |
| Push services | Deliver wakes: FCM, Web Push | from the relay |

## What Pombo adds

None of the building blocks was made for group chat. Each one needed a layer on top.

| Building block | What it provides | What it lacks | What Pombo adds |
| --- | --- | --- | --- |
| Streamr network | Signed pub/sub, without accounts | Its key exchange needs the publisher online | Members hand channel keys to each other on `-4` |
| Streamr registry on Polygon | Stream ownership and per-address permissions | Every change of access is a transaction | Closed, Gated and Paid channels grant access once, to a gate contract. Membership then follows its allowlist, a token balance or a payment |
| Storage nodes | History for members who were offline | No access checks on reads, no way to erase | `pombo-storage-node`: checks at ingest, signed reads, erasing, and the time each message was stored |
| Web Push, FCM | A way to wake a device that is not running | A relay that wakes devices per channel would learn who follows what | The relay knows neither who sends nor who receives. Wakes come from a fresh key, and devices register under a 1-byte tag shared by many channels. Each wake carries a proof-of-work |
| ENS | Names for addresses | Each lookup tells the RPC provider whose name you looked up | Two decoy lookups with each one |

## Discovery

- **Channels:** a listed channel says so in its stream metadata, so clients can find it through The Graph. An unlisted channel is found only by its ID.
- **Storage:** a stream's storage nodes are in Polygon's storage registry, their URLs in each node's on-chain metadata, and their features at `GET /capabilities`.
- **Relay:** its public key is in the push stream's metadata.

<Aside title="How the official clients do it">
The web app runs the Streamr SDK in the page. The Android app runs it in a hidden WebView. The account key passes through the WebView only when an account is created or imported; after that, a native signer answers every signing request.
</Aside>

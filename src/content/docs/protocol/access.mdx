| Type | Who can read | Who can write | Enforced by |
| --- | --- | --- | --- |
| Open | Anyone | Anyone | Network: public stream permissions |
| Protected | Anyone with the password | Anyone with the password | Encryption; others can publish only unreadable data |
| Closed | Accounts on the allowlist | Same | Gate contract, [epoch keys](/protocol/encryption/), storage nodes |
| Gated | Holders of a token or an NFT | Same | Same |
| Paid | Accounts with an active subscription | Same | Same |

## Read-only channels

Only the owner posts to `-1`, plus moderators in Closed, Gated and Paid channels; members still publish on `-2` and `-5`.

| Mode | Enforced by |
| --- | --- |
| Open, Protected | Network: `-1` grants publishing to the owner only |
| Sealed | Key holders: the key that signs `-1` is handed to the owner and moderators only |
| Visible | Readers drop `-1` messages from anyone else; storage nodes refuse to keep them |

The gate contract records the flag but does not check it.

## The gate contract

One contract per channel, cloned from a factory. The account that creates it is the owner.

- **Access order:** the owner passes, a banned account fails, a moderator passes, then the mode decides: allowlist, token balance, NFT, or paid subscription.
- **`checkAccess`** is strict. Key holders must ask it before handing out keys.
- **`isValidSignature`** (ERC-1271) is what the network asks when an account publishes through the gate: in Visible channels, and on `-4` in every mode. It passes messages if the token contract itself fails.
- **Set once, at creation:** owner, mode, token, minimum balance, identity on the wire, read-only.

| Call | Owner | Moderator |
| --- | --- | --- |
| `allow`, `allowBatch` (Closed) | yes | yes |
| `revokeAllow` (Closed) | yes | yes, except on the owner and other moderators |
| `ban`, `unban` | yes | |
| `setModerator` | yes | |
| `setPrice`, `setDuration` (Paid) | yes | |
| `pay`, `payWithPermit` | anyone, for themselves | |

- A ban keeps the allowlist entry, so an unban in a Closed channel restores access.
- Appointing a moderator in a Closed channel also allowlists them.
- `pay` extends a subscription from its current expiry and sends the payment straight to the owner. There is no grace period.

## Keys follow access

Key holders hand keys only to accounts `checkAccess` admits at that moment, and an admitted account receives every epoch the channel still retains. An account that loses access keeps what it already holds and loses the ability to read from the next epoch on.

## Identity on the wire

**Sealed** hides authors from the network behind shared keys. **Visible** publishes through the gate contract on each author's signature. See [Identity](/protocol/identity/).

## Storage nodes

At ingest a node checks the signature and the publish permission; for Visible channels that asks the gate. It caches a "yes" for 10 minutes and a "no" for 20 seconds. Reading gated history needs a read signed by an admitted account. See [Storage](/protocol/storage/).

<Aside title="How the official clients do it">
Key holders check access on two RPC endpoints; when they disagree, further endpoints break the tie, and an unresolved tie refuses. The owner's app starts a new epoch every week, and whenever it notices that an account lost access, so a lapsed member stops reading within a week at most. The apps pay subscriptions by wrapping POL if needed, approving, then calling `pay`.
</Aside>
